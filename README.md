# FraudLens: AI-Based Credit Card Fraud Detection System

**Explainable hybrid machine learning that detects suspicious card transactions in real time, scores their risk and explains every decision.**

Domain: Cyber Security / Forensics · Machine Learning / Data Security

FraudLens turns every card transaction into behavioural features computed from that card's own history. Three
detectors score it: **XGBoost** and **Random Forest** learn known fraud patterns, and **Isolation Forest** flags
behaviour unlike normal spending. A stacking meta-learner combines them into a calibrated fraud probability, which
becomes a **0-100 risk score** and a decision (**Approve / Step-up verification / Block**). Every decision carries
plain-language **SHAP reasons** and is written to an auditable decision log. A **FastAPI** service scores
transactions in a fraction of a second, and a **React dashboard** is used to monitor, test, investigate and present.

## Web, app or model? The verdict

**A web platform (real-time REST API + dashboard) powered by a hybrid ML model.** Fraud scoring must run
server-side inside the payment-authorisation path, with access to every card's history, so a phone app cannot be the
core. On the same data and split, deep models (MLP, 1D-CNN) were less accurate, slower and harder to explain than
gradient-boosted trees, so a single "special" deep model is not the answer either. A mobile app is a natural future
client of the same API (customer "Was this you?" alerts).

## Architecture

```
 Transaction ──► Feature store (card history, 39 causal features, ~0.07 ms)
                     │
        ┌────────────┼──────────────────┐
        ▼            ▼                  ▼
     XGBoost    Random Forest    Isolation Forest (trained on genuine only)
        └────────────┼──────────────────┘
                     ▼
        Logistic stacking meta-learner  ──►  calibrated fraud probability
                     ▼
        Risk score 0-100 ──► LOW: Approve · MEDIUM: Step-up (OTP) · HIGH: Block
                     ▼
        TreeSHAP reason codes ──► decision log (audit trail) ──► React dashboard
```

## Quick start (run the demo)

The trained models and the held-out test data are included, so the demo runs without re-training.

```powershell
git clone https://github.com/Prateek22672/AI-Based-Credit-Card-Fraud-Detection-System.git
cd AI-Based-Credit-Card-Fraud-Detection-System
python -m venv .venv
.venv\Scripts\pip install -r requirements.txt

# 1) API  ->  http://localhost:8000/docs
.venv\Scripts\python -m uvicorn fraudlens.api.main:app --port 8000

# 2) Dashboard (second terminal)  ->  http://localhost:5173
cd frontend
npm install
npm run dev
```

To serve everything from one port, run `npm run build` in `frontend/` and open http://localhost:8000.

## Test

```powershell
.venv\Scripts\python -m pytest            # leakage, parity, metrics and API tests
```

Interactive API docs: http://localhost:8000/docs. For example, score a transaction with `POST /api/score`
(get a card token from `GET /api/cards`).

## Present it (about 10 minutes)

1. **Overview**: the problem, the verdict and the headline numbers.
2. **Live Monitor**: press *Start*. These are unseen April-June 2020 transactions replayed in time order; alerts appear and live precision/recall converge.
3. Click a **HIGH** row: read the reasons and the three detector votes.
4. **Scam Scenarios**: run *Card testing*, then *Normal day*, and compare the risk curves.
5. **Transaction Tester**: a card's usual purchase is LOW; the same card at $1,150 online at 02:30 is HIGH.
6. **Case Queue**: confirm or dismiss an alert and open the audit record.
7. **Results**: E3 (how shortcuts inflate published numbers) and E4 (features matter most).
8. **Project Report**: milestones and work distribution.

## Deploy on your own domain

* **One server (simplest):** `docker build -t fraudlens .` and `docker run -p 8000:8000 fraudlens`, then point the domain
  (Nginx reverse proxy or a Cloudflare Tunnel) at the port. The container serves both the API and the dashboard.
* **Split hosting:** build the dashboard with `VITE_API_URL=https://api.your-domain npm run build`, upload `frontend/dist`
  to any static host, run the API on a VPS and set `FRAUDLENS_CORS_ORIGINS=https://your-domain`.
* For public demos set `FRAUDLENS_API_KEY` (and `VITE_API_KEY` at build time) and a private `FRAUDLENS_TOKEN_SECRET`.

| Variable | Purpose |
|---|---|
| `FRAUDLENS_DB_URL` | Decision-log database (default SQLite in `artifacts/`; e.g. `postgresql+psycopg://...`) |
| `FRAUDLENS_API_KEY` | Require `X-API-Key` on state-changing endpoints |
| `FRAUDLENS_CORS_ORIGINS` | Allowed dashboard origins (comma-separated) |
| `FRAUDLENS_TOKEN_SECRET` | Secret for card-number tokenisation |

## Datasets

* **Sparkov** simulated card transactions (Kaggle `kartik2112/fraud-detection`, generated with the open-source Sparkov generator), 1,296,675 transactions, 2019-01 to 2020-06.
* **ULB / Worldline** European card transactions (Kaggle `mlg-ulb/creditcardfraud`; Dal Pozzolo et al., 2015), 284,807 transactions, 492 frauds.
